# RGS–STEM Interoperability Profile (Proposal v0.1)

**Status:** proposal for technical discussion; not an Ontos extension approved by Stem Framework.  
**Scope:** deterministic exchange and independent verification of finite algebraic, geometric and spectral benchmark data.  
**Normative principle:** preserve the current Ontos stream specification unchanged.

## 1. Purpose

This profile defines a conservative first bridge between the existing RGS–QLG implementation and the Stem Framework.

The current RGS repository already contains implementations and tests for:
- scalar-first Hamilton quaternions and SU(2)/SO(3) lifts;
- the 64-vertex, 192-edge, 240-face Q6 complex and integer incidence matrices;
- the 120-element binary icosahedral group and selected representations/intertwiners;
- Möbius-complex local-frame and gauge-covariance audits;
- Clifford algebra conventions and spatial spinor action;
- discrete Dirac, Dirac–Kähler and overlap-operator experiments;
- a flat periodic-torus Mosco-convergence prototype.

The first bridge should package existing, explicitly selected outputs. It must not silently regenerate missing RGS data or replace current mathematical conventions.

## 2. Compatibility rule

The current Ontos Stream Specification is normative and rejects unknown record tags. Therefore this proposal does **not** add undocumented record types to Ontos v1 or v2.

The initial interoperability mechanism is a separate, versioned sidecar package:

    manifest.rgsstem.json
    arrays/
    reports/
    streams/   (optional existing Ontos stream)

An Ontos stream remains valid and independently verifiable under its own specification. RGS sidecar data are verified by a separate RGS verifier until Stem explicitly agrees to a versioned extension or a registered sidecar convention.

## 3. Package layout

    benchmark/

      arrays/

        2i_quaternions.f64le

        operator_matrix.c128le
      reports/
        audit.json
        summary.md
      streams/
        optional-ontos-stream.onto

Only files actually generated by the selected reference implementation may be included. The example names above describe roles, not a claim that these files already exist.

## 4. Manifest contract

The manifest is UTF-8 JSON. Producers should serialize object keys in lexicographic order, use no insignificant whitespace, and reject non-finite floating-point values (NaN and infinities).

Required top-level fields:

- profile: exactly rgs-stem-interoperability;
- profile_version: semantic version string, initially 0.1.0;
- benchmark_id: stable identifier;
- producer: repository URL, commit SHA, module and function;
- conventions: indexing, orientation, basis, multiplication and operator conventions;
- objects: named arrays or structured finite objects;
- checks: named verification claims, status, tolerance and measured residual;
- payloads: file path, dtype, shape, byte order and SHA-256;
- ontos_reference: optional stream path and SHA-256; null when no Ontos stream is involved.

Each array descriptor must specify:
- unique logical name;
- scalar type (i8, i32, i64, f64, or c128);
- shape;
- row-major storage order;
- little-endian byte order for multi-byte scalars;
- exact payload path and SHA-256.

Complex arrays use interleaved binary64 real and imaginary components in C row-major order. Quaternion arrays must additionally declare component order; this repository's Hamilton convention is scalar-first unless a specific adapter explicitly converts it.

The SHA-256 digest is an integrity check for payload identity, not a proof of mathematical correctness. Ontos FNV-1a64 hashes retain their separate role in Ontos stream verification.

## 5. Canonical conventions to preserve

### 5.1 Q6

- Vertex IDs: six-bit big-endian integer labels, 0 through 63.
- Axis 0 flips the most significant bit; axis 5 flips the least significant bit.
- Edges: oriented from the smaller integer vertex ID to the larger.
- Faces: ordered axis pair (a,b), a<b, with boundary v → v^a → v^(a,b) → v^b → v.
- Incidence matrices: B1 in Z^(64×192), B2 in Z^(192×240).
- Required exact identity: B1 B2 = 0.

The 240 square faces of Q6 must not be confused with the separate six-face Möbius test subcomplex.

### 5.2 Binary icosahedral group

- Group: 2I contained in SU(2), order 120.
- Quaternion convention: scalar-first Hamilton convention unless explicitly declared otherwise.
- The central element -1 must remain distinguishable from +1 in spinorial representations, even though both project to the identity rotation in SO(3).
- Every representation must declare its basis ordering and whether matrices are real or complex.

### 5.3 Clifford and Dirac data

Every Clifford payload must declare:
- metric signature;
- anticommutator convention;
- gamma-matrix basis and ordering;
- grade ordering for multivectors;
- whether the operator is spatial, Euclidean, or Lorentzian;
- domain, boundary conditions, inner product and adjoint convention.

A spatial Dirac candidate, Euclidean Wilson kernel, overlap operator and cochain Dirac–Kähler operator are distinct objects. They must have distinct operator_kind identifiers and must never be merged into one generic Dirac matrix.

## 6. Verification record semantics

Each check has:
- check_id;
- claim_class: PROVED, NUMERICALLY_VERIFIED, CANDIDATE, or OPEN;
- method;
- expected;
- observed;
- residual (when numerical);
- tolerance (when numerical);
- implementation_independence: same-code, separate-module, or independent-implementation.

A numerical pass must never be promoted automatically to a proof. A hash match establishes payload identity, not correctness of the underlying mathematics.

## 7. First benchmark: 2I → Q6 → Clifford/Dirac

The first package should be staged in the following order.

### B0 — Provenance and conventions
Record repository commit SHA, Python and NumPy versions, random seeds, all input hashes, and exact convention metadata.

### B1 — Q6 incidence
Export B1 and B2. Independently verify dimensions, integer entries, vertex degree six, face boundaries and exact B1 B2 = 0.

Expected structural values:
- vertices: 64;
- edges: 192;
- square faces: 240;
- degree: 6;
- shape(B1) = (64,192);
- shape(B2) = (192,240).

### B2 — 2I algebra and selected representations
Export the 120 quaternion elements, group multiplication convention and selected representation matrices. Verify closure, inverses, representation homomorphism, unitarity/orthogonality and central-element action.

The existing selected representation set must not be described as the complete irreducible character table unless that table is separately constructed and verified.

### B3 — Clifford algebra
Export gamma matrices and the declared basis. Independently check

    gamma^mu gamma^nu + gamma^nu gamma^mu = 2 eta^(mu,nu) I.

Check grade decomposition and reconstruction.

### B4 — Operator-specific spectral data
Export each operator separately, with matrix shape, dtype, adjoint convention and operator kind. Verify Hermiticity or the declared gamma5-Hermiticity relation, eigenpair residuals, multiplicities and relevant symmetry relations.

### B5 — Independent replay
A verifier that does not import the producer's construction functions should:
1. parse the manifest;
2. validate payload hashes and array dimensions;
3. reconstruct the finite algebraic checks;
4. recompute the declared residuals and spectral summaries;
5. emit a machine-readable audit report.

Only after this finite benchmark is stable should a dynamic Ontos integration be proposed.

## 9. Ontos integration boundary

The first release is a static benchmark package. It does not require Ontos to simulate quaternionic or spinorial fields.

If a future dynamic experiment is desired, the parties should agree on one of:
1. a formally specified Ontos version increment with registered record tags;
2. a documented sidecar convention linked to a valid Ontos stream;
3. a separate deterministic adapter whose output is checked independently by simval.

No choice should be assumed on behalf of Stem Framework. The verifier must reject unknown tags exactly as required by the current Ontos specification.

## 10. Acceptance criteria

The first shared benchmark is ready for external review when:
- all payloads have stable hashes and declared shapes/dtypes;
- Q6 incidence identities pass exactly;
- the selected 2I group and representation checks pass;
- Clifford identities pass under the declared signature;
- each operator has a precise mathematical definition and independent audit;
- all numerical residuals and tolerances are included;
- an independent verifier can reproduce the report without importing producer functions;
- unsupported physical interpretations are explicitly excluded from the benchmark verdict.

## 11. Evidence boundary and open questions

This profile validates finite data exchange and reproducibility. It does not establish:
- a continuum limit for the fixed Q6 complex;
- a physical interpretation of the 2I quotient;
- a derivation of Einstein or Einstein–Cartan dynamics;
- a physical model of antimatter or black holes;
- a complete Lorentz-group representation;
- Mosco convergence for a nonuniform RGS refinement family.

The flat periodic-torus Mosco prototype is a separate result and must not be presented as a proof for the RGS refinement family.
